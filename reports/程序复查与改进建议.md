## 下一阶段建议按以下顺序实施

### 第一优先级 受控改派等待乘客

当前模型是一人一次派单。电梯后来空闲时，其他车上积压的候梯请求也不会重新评估。这是已声明的建模限制，值得作为独立实验开关研究。

可复现实例：12层、2台电梯、容量1、仿真120秒、高峰中心40秒，其余默认；使用ETA策略。

```python
requests = [
    Request(0, 0,   1, 12),
    Request(1, 0,   1, 2),
    Request(2, 0.1, 1, 2),
]
```

乘客2在0.1秒被分给E1（内部编号0），77.6秒才上车，等待77.5秒。E2约12秒结束服务后已经空闲在2楼；20秒快照显示，1楼有人候梯而E2仍空闲。快照与结果见 `review_regression.json`。

建议只允许改派尚未上车且未进入上车动作的请求；对即将到站的承诺设置保护。采用最小ETA收益、冷却时间及改派次数限制，并完整记录原因。所有策略公平使用同一开关，分别报告开关前后结果。实现时要防止乘客在上车耗时进行中被其他车“接管”，也要避免反复改派震荡。

验收目标：这个案例的等待显著缩短，无重复上车、无容量越界；对上行、下行、混合、课间客流分别做多种子比较。不能仅凭此例宣布所有场景都改善。

### 第二优先级 增加到达结束后的排空实验

保留当前在T时刻截止的全部指标，再提供可选“停止到达后继续服务至全部送达”模式，记录额外运行时间、最终等待和最终路程，并设置合理安全时限及未完成提示。这样可以补充同一批乘客的最终体验，减少不同策略截止时已上车人群不同带来的比较困难。

实现应使用“全部送达”事件终止，不能直接无限期 `env.run()`，因为周期调度进程会持续产生事件。当前截止口径无需取消，它能回答固定时段内的服务能力问题。

### 第三优先级 用实际客流校准并比较多目标

先导入脱敏实际客流，校准楼层行驶、门控、上下客时间以及峰值分布；增加不同负载、不同种子和不同时段。除平均等待外，至少同时比较P95、未服务人数、完成率和空载距离。

本项目已有结果表现为等待降低、空载距离增加。建议调节预定位的路程惩罚，并绘制等待与空载距离的取舍曲线。没有真实电机参数和实测数据前，不把楼层跨度称为节电量。

### 第四优先级 保存加载实验与演示预设

目前可以导出实验包，但不能在界面加载并播放。建议支持导入自己的实验包，校验格式版本、楼层范围、帧时间顺序和容量，再离线回放。该功能能方便上台展示，也能比较不同版本的结果。

先实现已记录轨迹的播放；恢复整个SimPy运行状态是另外一个更复杂的功能，应单独设计。可增加早高峰、晚高峰、课间和超载四个固定演示预设，但参数和结果必须实际计算。

### 第五优先级 拆分策略并减少重复扫描

将派梯评分提取为统一接口，把界面表格、回放和实验控制分开。维护待派单集合和按楼层分组的候梯队列，减少遍历已送达历史乘客与反复构造停站集合。

复查实测中，同一配置关闭回放的单策略运行，500、1000、2000个请求分别约0.05、0.13、0.42秒，显示高客流下存在非线性增长；该测量用于定位性能方向，不代表默认500余人的实验不能使用。重构前后必须保持固定输入的逐客结果一致，并对大CSV另做耗时和内存验证。
