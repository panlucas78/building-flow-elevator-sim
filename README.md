## 2. 已完成的改造

- 每位乘客独立记录到达、起终点、分配、上车、送达和状态。

- 用 LOOK 规则维护方向、停站和反向，修复夹在两个目标楼层之间无法移动的问题。

- 提前生成同一批客流供所有策略回放，仿真执行阶段不再使用随机上下客。
- 提供就近、ETA、ETA+SLP、ETA+预测预定位、完整自适应五种策略，默认展示三种。
- 新增平均等待、P95、全程耗时、完成率、未服务人数、平均队长、运行与空载距离。
- 新增楼宇回放、乘客筛选、调度原因、CSV 导入、完整实验 ZIP 和多种子消融验证。
- 不强制输出正向改善；所有图表与差值按实际仿真结果展示。

## 3. 如何使用

1. 在左侧选择楼层、电梯、容量、场景、时长、客流与随机种子，点击「运行公平对比」。首次进入自动运行默认实验。
2. 「对比总览」查看队列、完成运送、指标、实际客流和滚动预测。
3. 「楼宇回放」选择策略，播放、暂停、单步或拖动时间轴。灰色为空闲、青色为运行或门控、橙色为满载。
4. 「乘客与调度」检查每位乘客时间戳、未服务状态和分配原因。
5. 「批量验证」对多个随机种子比较策略，可以单独启用 SLP 和预测做消融分析。
6. 下载实验包，其中包含参数、请求 SHA-256、全部乘客、日志、指标和回放数据。

### 导入 CSV

UTF-8 编码，固定四列：

```csv
id,arrival,origin,destination
0,0,1,6
1,2.5,8,1
```

`id` 必须是唯一整数；`arrival` 单位为秒且满足 `0 <= arrival < 仿真时长`；起终点不同，楼层从 1 开始。最多 25000 人、5 MiB。表头不得重复或为空，每行列数须与表头一致。侧栏导入后点击运行，系统将以文件请求为准，客流生成参数不再决定到达请求。`sample_requests.csv` 是可直接试用的 12 层示例。

## 4. 关键建模约定

### 信息公平

这是常规方向呼梯模型：调度时只读取已到达乘客的起点、方向，以及电梯当前状态；乘客目的地在上车后进入停靠计划。生成器和导出数据保留目的地，用于运输仿真与核对。调度器不读取未来到达请求。

请求按到达时间和 id 排序，同一时间到达的乘客先统一加入再分配。已分配请求由一台电梯持续负责，不在每个时刻重复派单；在门口按到达顺序上车。空车会优先处理等待超过阈值的已分配乘客，但这不是硬性等待上限保证。

### 策略

所有策略共享容量筛选和 LOOK 行驶规则。

- **就近**：距离最短，平局时选任务更少的电梯。
- **ETA**：根据当前方向、折返、已有停站、剩余动作时间与任务量估计接客耗时。ETA 为近似评分，不是精确承诺。
- **SLP**：对楼层分区关联给予有上限的秒数加分。先验分为大堂、低区教学、高区办公；用已完成行程的 OD 频次逐步融合，避免偷看未上车目的地。
- **预测**：用过去两个60秒窗口的分楼层到达率做 0.7/0.3 平滑和阻尼趋势，预测未来60秒到达人数。只给空闲电梯做预定位，并使用距离成本和覆盖惩罚，预定位行驶计入空载距离。

所有场景使用一秒分段的泊松到达率：`基础率 + 额外峰值率 × exp(-((t-中心)/宽度)^2)`。早高峰以上行为主，晚高峰以下行为主，混合和课间场景改变起终点分布。当前都是合成假设，尚未用真实楼宇数据校准。

### 指标和截止处理

- 平均等待、P95 和最大等待：只统计已经上车的乘客，必须同时查看上车率与未服务人数。
- 平均乘梯 / 全程时间：只统计已送达乘客。
- 全体已观察等待：已上车者计到上车时刻；未上车者计到仿真截止，属于截断观察值，不能代替最终等待。
- 平均队长：所有乘客已观察等待时间之和 / 仿真时长，等于候梯人数的时间积分平均。
- 总距离 / 空载距离：单位为楼层跨度，包含截止时正在运行路段的已行驶部分；空载按该路段开始时车内人数判断。不能直接称为节电量。
- 到达区间 `[0,T)`，仿真截止于 `T`；恰在 `T` 完成的内部事件尚未处理，状态计入未完成。结束时不会额外清空队列。
- 批量报告的 95% 区间使用配对差值的正态近似；小样本只作探索，且各策略已上车人群可能不同。

模型暂不覆盖加速度、乘客重量和群组、真实电机能耗、故障、安全控制及硬件接口。

## 5. 验证与命令行实验

运行回归测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -p 'test_*.py' -v
```

也可双击 `run_tests.cmd`。测试覆盖手算运输时间、卡梯回归、请求完成、容量、同层多人、方向、截断统计、部分路段距离、空客流、共享请求、确定性、预测因果性和导出完整性。

运行 5 个种子 × 5 种策略（命令行高峰中心设为总时长的 1/3）：

```powershell
.\.venv\Scripts\python.exe eos.py --batch --seeds 5 --seed 42 --duration 3600 --scenario up_peak --output reports
```

生成 `reports/benchmark.json` 和 `reports/benchmark.csv`。种子42~46的初次结果已保存，可自行复算。侧栏默认高峰位置为总时长33%，与命令行的1/3存在少量差异；精确复现以导出参数和请求指纹为准。
